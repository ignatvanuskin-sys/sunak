# СТО «Сунақ» — сайт с системой онлайн-записи

Готовый коммерческий сайт для автосервиса **«Сунақ»** (Астана, ул. Озбекали Жанибек, 30Б).
Статический лендинг: чистый HTML + CSS + JS, без сборки и зависимостей.

---

## 1. Что внутри

```
index.html                    — весь лендинг (семантическая разметка, SEO, Schema.org)
robots.txt
assets/
  css/styles.css              — дизайн-система и адаптив
  js/app.js                   — мастер записи, календарь, галерея, меню, модальные окна
  favicon.svg
  img/opt/                    — оптимизированные фотографии (.webp + .jpg)
api/
  booking.example.js          — пример backend-обработчика заявок (Telegram-уведомление)
_data/                        — рабочие материалы исследования (можно не загружать на хостинг)
  originals/                  — исходные фото из 2ГИС
  reviews_p1.json, reviews_p2.json, reviews_readable.txt
  parse_reviews.py, prepare_images.py
_qa/                          — скриншоты и отчёт тестирования
```

## 2. Как открыть

Локально (рекомендуется — так работают все ссылки и карта):

```bash
cd "путь/к/сунак"
python -m http.server 8080
# открыть http://127.0.0.1:8080
```

Либо просто открыть `index.html` в браузере — вся вёрстка и мастер записи работают,
но встроенная карта может не загрузиться из-за ограничений `file://`.

## 3. Система записи: как она работает сейчас

Форма записи собрана как мастер из 4 шагов: **услуга → дата → время → контакты**.
Есть валидация, маска телефона `+7 XXX XXX XX XX`, состояния загрузки/ошибки/успеха,
сохранение черновика в `sessionStorage` и экран успеха со сводкой заявки.

Отправка работает в одном из двух режимов — переключается одной строкой в `assets/js/app.js`:

| Режим | Что происходит | Как включить |
|---|---|---|
| **WhatsApp** (включён по умолчанию) | Заявка собирается в готовое сообщение и передаётся в WhatsApp компании. Никаких «фальшивых» подтверждений: интерфейс прямо говорит пользователю, что осталось отправить сообщение. | ничего делать не нужно |
| **Backend** | Заявка уходит POST-запросом (JSON) на ваш API, администратор получает уведомление. | указать `BOOKING_CONFIG.endpoint` |

### Включение реального backend

1. Скопируйте `api/booking.example.js` в свой проект как `api/booking.js`
   (Vercel Functions / Netlify Functions / любой Node-хостинг).
2. Задайте переменные окружения:
   `TELEGRAM_BOT_TOKEN` (бот от @BotFather) и `TELEGRAM_CHAT_ID` (id администратора или группы).
3. В `assets/js/app.js` укажите:

```js
var BOOKING_CONFIG = {
  endpoint: '/api/booking',
  whatsapp: '77753375793',
  phone: '+77753375793',
  business: 'СТО «Сунақ»'
};
```

После этого заявка уходит на сервер, а администратор получает сообщение вида:

```
Новая запись — СТО «Сунақ»

Имя: Иван
Телефон: +7 775 337 57 93
Услуга: Аргонная сварка
Дата: 2026-10-12
Время: 14:30
Комментарий: корпус КПП, нужна сварка
```

Payload, который отправляет форма:
`name`, `phone`, `service`, `date`, `time`, `comment`, `source`, `createdAt`.

### Данных нет — и они НЕ придуманы

В карточке компании отсутствуют, поэтому на сайте их нет:

- **прайс-лист и цены** — вкладка «Цены» в 2ГИС пустая. Вместо выдуманных цифр
  в каждом блоке услуг стоит «Цена по запросу», а отдельный блок «Честно о ценах»
  объясняет, как цену узнать;
- **текстовое описание компании** — поле пустое; блоки «О компании» и «Почему мы»
  собраны из рубрик и отзывов;
- **социальные сети и сайт** — не указаны ни в 2ГИС, ни найдены в поиске
  (по адресу и названию). Instagram-аккаунты, которые удалось найти, принадлежат
  другим компаниям, поэтому ссылки на них не добавлены;
- **год основания, марки авто, гарантия, парковка, эвакуатор** — не заявлены.

Ответ в FAQ про гарантию сформулирован честно: условия не заявлены, их нужно
уточнять у мастеров. Так лучше, чем выдуманная «гарантия 2 года».

## 5. Дизайн

- **Цвета взяты с реальной вывески компании:** жёлтый `#FFC400` по тёмно-графитовому
  `#0A0B0D` — именно так выглядит вывеска «СТО» на фасаде и «СУНАК» в цехе.
  Плюс нейтральные серые и один акцент для WhatsApp.
- **Типографика:** Manrope (кириллица + латиница), крупные заголовки `clamp()`,
  один `H1`, иерархия `H2`/`H3`.
- **Композиция:** premium-структура лендинга (eyebrow → крупный заголовок → короткий
  лид → два CTA → визуальный блок), bento-галерея, карточки, рейтинговый блок.
- **Анимации:** только fade-up при скролле, hover-переходы, плавные модальные окна.
  Всё отключается через `prefers-reduced-motion`.

## 6. Мобильная версия

- адаптив проверен на 320 / 360 / 390 / 430 / 768 / 1024 / 1280 / 1440 px;
- фиксированная нижняя панель `Позвонить | WhatsApp | Записаться` с учётом
  `env(safe-area-inset-bottom)`; у `body` есть компенсирующий `padding-bottom`,
  поэтому панель не перекрывает контент;
- компактный header с бургер-меню и крупными touch-target (≥ 42–54 px);
- на мобильных мастер записи открывается как bottom-sheet.

## 7. SEO и доступность

- `<title>`, `meta description`, Open Graph, favicon, `robots.txt`;
- один `H1`, корректная иерархия заголовков, `alt` у всех изображений;
- JSON-LD `AutoRepair` с адресом, координатами, графиком, телефоном, способами оплаты
  и `aggregateRating` (4,8 / 151) — данные реальные;
- семантические `header/nav/main/section/footer`, `fieldset`/`legend` в форме,
  `aria-label`, `aria-modal`, `role="alert"` для ошибок, скрытые подписи;
- видимый фокус (жёлтый контур), skip-link, ловушка фокуса в модальных окнах,
  закрытие по Esc, поддержка клавиатуры в галерее.

**Перед публикацией нужно заменить:** `og:url` и `og:image` в `index.html` на абсолютные
адреса реального домена, добавить`<link rel="canonical">` и `sitemap.xml`.

## 8. Производительность

- изображения: WebP + JPEG-фолбэк, ширина до 1200 px, hero — 84 КБ WebP;
  `loading="lazy"` и `decoding="async"` у всех, кроме hero (`fetchpriority="high"`);
- шрифты: Google Fonts с `display=swap` и неблокирующей загрузкой;
- JS: один файл без фреймворков, `defer`;
- карта OpenStreetMap подгружается только при подъезде к блоку «Контакты».

## 9. Что стоит сделать дальше

1. **Получить реальный прайс-лист** у владельца — тогда блок «Цены» превратится
   в полноценную таблицу услуг с ценами (структура уже готова).
2. **Подключить backend** (`api/booking.example.js`) — чтобы заявки приходили
   в Telegram, а не только в WhatsApp.
3. **Уточнить гарантию и марки авто** — как только будут подтверждены, их можно
   добавить в блок преимуществ и FAQ.
4. **Подтвердить фото** — сейчас на сайте 8 реальных фото из 2ГИС (с водяным знаком
   2ГИС в углу). Для коммерческого запуска лучше заказать собственную фотосессию:
   фасад, цех, станки, процесс сварки.
5. **Разобраться с негативными отзывами.** В 2ГИС у компании 44 отзыва на 5★ и
   17 отзывов на 1★; почти все негативные — про токаря и про расхождение цены
   «по телефону и на месте». На сайте показаны реальные отзывы и реальный средний
   рейтинг, но владельцу стоит ответить на критику — это влияет на конверсию сильнее,
   чем любой редизайн.
6. **Домен и хостинг** — сайт статический, подойдёт любой (Vercel, Netlify, обычный
   хостинг). Достаточно загрузить файлы `index.html`, `robots.txt`, `assets/`.

## 10. Тестирование

Сайт протестирован в браузере на реальных ширинах 320–1440 px: проверены
горизонтальный скролл, header, нижняя панель, модальные окна, мастер записи,
валидация, маска телефона, фильтры услуг, галерея с лайтбоксом, FAQ, мобильное меню,
карта и консоль. Отчёт и скриншоты — в папке `_qa/`.

Найденные при тестировании баги были исправлены:

| Проблема | Причина | Исправление |
|---|---|---|
| Горизонтальный скролл на 320–360 px | `white-space:nowrap` у кнопок + флекс/грид-дети не сжимались | разрешён перенос текста в кнопках, добавлены `min-width:0` и `minmax(0,1fr)` |
| Мобильное меню не открывалось | базовый `.nav{display:none}` не сбрасывался в медиазапросе | в мобильном медиазапросе задан `display:flex` |
| В мастере записи одновременно были видны все кнопки | авторский `display` у `.btn` перебивал браузерное `[hidden]{display:none}` | добавлено правило `[hidden]{display:none !important}` |
| На 1024 px шапка переносила телефон на вторую строку | не хватало места | телефон показывается от 1180 px, навигация компактнее |
| Кнопки «Позвонить» в первом экране и «Закрыть» на экране успеха были **невидимы** | класс `btn--ghost` был рассчитан на тёмный фон: белый текст и белая рамка на белых секциях | для первого экрана используется `btn--outline`, самом `btn--ghost` задан тёмный текст для светлого фона |
| Мелкий серый текст не проходил WCAG AA по контрасту | один токен `--muted-2` использовался и на светлом, и на тёмном фоне | введены отдельные токены: `--muted-2` (#6B7280) для светлого фона и `--muted-d2` (#9BA3AB) для тёмного |

Проверенные контрасты после правок (WCAG): `.caption-note` 4,83:1 · `.trustbar__v` 4,83:1 ·
`.review__head time` 4,83:1 · `.final__note` 7,71:1 · `.footer__bottom` 7,09:1 — все ≥ 4,5:1.
